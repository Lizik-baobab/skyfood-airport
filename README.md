# SkyFood Airport — Figma-aligned React frontend

Самостоятельная сборка React + Vite (JavaScript), ориентированная на Figma-файл `SKYFOOD`, фреймы:
- `01 · Рейсы` — `59:620`
- `02 · Карточка рейса` — `44:21`
- `03 · Отчёты` — `105:164`
- `04 · Отчёт по рейсу` — `59:820`

## Запуск

```bash
npm install
npm run dev
```

Vite покажет локальный адрес, обычно `http://localhost:5173`.

## Навигация

- `/flights` — список рейсов
- `/flights/:id` — отдельная страница рейса (не модальное окно)
- `/reports` — список финансовых отчётов
- `/reports/:id` — отдельная страница финансового отчёта

Кнопки «Открыть рейс» и «Открыть отчёт» переводят на отдельные маршруты. Работают хлебные крошки и кнопки возврата.

## Визуальный стиль

Использованы параметры Figma: sidebar `#0F2B52`, active navigation `#1F4F85`, фон `#F2F7FC`, поверхности `#FFFFFF`, основной текст `#29384F`, приглушённый текст `#7A8A9E`, границы `#E3EBF2`, синий action `#2463B5`, зелёный success `#297A57`, шрифт Nunito.

## Финансовые отчёты

В режиме моковых данных показываются три явно обозначенных демонстрационных отчёта. В реальном режиме список и детализация отчётов загружаются с backend.

В финансовый отчёт должны попадать только ваучеры, выданные пассажирам из-за задержки конкретного рейса. Backend определяет право на выдачу ваучеров, момент формирования итогового отчёта и сумму возмещения. Frontend не устанавливает порог задержки и не вычисляет задолженность самостоятельно.

Поддерживаемые маршруты интеграции:
- `GET /api/v1/flights`
- `PATCH /api/v1/flights/{flightId}`
- `GET /api/v1/reports/flights`
- `GET /api/v1/reports/flights/{flightId}`

Точные JSON-контракты необходимо сверить с Java backend. Если названия полей отличаются, адаптировать `src/services/api.js` и отображение данных в `ReportDetailPage.jsx`.

## Режим backend

Создайте `.env` на основе `.env.example`:
```env
VITE_API_BASE_URL=http://localhost:8080
VITE_USE_MOCK_API=false
```
После изменения `.env` перезапустите Vite. Браузер обращается только к Java REST API, напрямую к PostgreSQL он не подключается.

## Демонстрационные данные

В `src/data/demoFlights.js` сохранены 21 демонстрационный рейс для просмотра и проверки интерфейса. Это не реальное расписание. Изменения статусов и задержки в mock-режиме сохраняются в `localStorage` под ключом `skyfood_airport_flights_v2`.

## Важно

Это замена предыдущего неудачного архива, созданная по структуре и визуальным параметрам указанного Figma-файла. Поскольку исходный локальный проект и его последние изменения не были доступны для полного сравнения, перед заменой сохраните резервную копию старой папки.


## Демонстрационные рейсы и отчёты (ноябрь 2026)

В режиме `VITE_USE_MOCK_API=true` используются 21 согласованный демонстрационный рейс и 3 моковых финансовых отчёта: SU1001 (150 минут), S71001 (270 минут), U61001 (390 минут). Остальные 18 рейсов оставлены без изменений.

Моковые отчёты находятся в `src/data/demoReports.js`. Количество выданных ваучеров отражает модель для 15 пассажиров: SU1001 — 15 WATER; S71001 — 15 WATER + 15 MEAL; U61001 — 15 WATER + 15 MEAL. Второй MEAL для U61001 не добавляется. В таблице заказов каждая строка — отдельное погашение одного ваучера одним пассажиром; в составе заказа всегда одна единица товара. Если пассажир использовал WATER и MEAL, это две отдельные строки с разными типами ваучера. Суммы условные и предназначены только для демонстрации интерфейса.

Для исключения старых тестовых данных используется новый ключ localStorage `skyfood_airport_flights_v3`. Если браузер всё же показывает прежние данные, очистите этот ключ в Local Storage или откройте проект в приватном окне.
